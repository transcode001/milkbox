# Codex 向けプロンプトテンプレート

milkbox リポジトリで Codex(またはCLIエージェント)にタスクを依頼する際のテンプレート集です。`[ ]` の部分を埋めて使ってください。リポジトリ全体のコンテキストは [`AGENTS.md`](../AGENTS.md) を自動的に読む前提のテンプレートなので、構成・規約の説明は繰り返していません。

---

## 1. バグ修正

```
milkbox リポジトリで発生しているバグを修正してください。

## 症状
[何が起きているか。再現手順があれば記載]

## 期待する挙動
[本来どうあるべきか]

## 関連箇所(わかれば)
[ファイルパス、画面名、コンポーネント名など]

## 完了条件
- 原因を特定し、根本原因を修正する(対症療法・try-catchでの握りつぶしは避ける)
- 影響するパッケージで `pnpm lint` / `pnpm check-types` / `pnpm test` を実行し、通ることを確認する
- 変更範囲は最小限にし、無関係なリファクタリングは含めない
```

---

## 2. 新機能実装

```
milkbox リポジトリに新しい機能を実装してください。

## やりたいこと
[機能の概要]

## 対象アプリ
[apps/mobile | apps/web | apps/docs | apps/desktop のいずれか、または複数]

## 要件
[箇条書きで具体的に。UI要件があればFigmaリンクや参考画像も]

## 完了条件
- 既存の設計・命名規約に合わせる(該当パッケージの既存コードを読んで倣うこと)
- 影響するパッケージで `pnpm lint` / `pnpm check-types` を実行し、通ることを確認する
- apps/mobile への変更の場合は `pnpm test` も実行する
- UIの変更がある場合は実際に起動して動作確認する(型チェック・lintだけでは機能の正しさは保証されない)
```

---

## 3. コードレビュー依頼

```
milkbox リポジトリの現在の差分をレビューしてください。

対象: [git diff <base>...HEAD / 特定ファイル / PR番号]

観点:
- 正しさ(ロジックの誤り、null/undefined、境界値、非同期処理の考慮漏れ)
- 削除された処理が別の場所で肩代わりされているか
- 変更箇所を呼び出している他のファイルへの影響
- 車輪の再発明(既存の @repo/core・@repo/ui・@milkbox/shared にある機能の重複実装)
- 過剰な複雑さ・不要な抽象化
- モバイル固有: apps/mobile/android や apps/mobile/ios が誤ってコミットされていないか、EAS/署名鍵まわりに問題がないか

各指摘には該当ファイル・行、具体的な失敗シナリオ(どんな入力・状態で問題が起きるか)を添えてください。指摘の重大度が高い順に並べてください。
```

## 4. テスト追加

```
milkbox リポジトリの [対象パッケージ/ファイル] にテストを追加してください。

## 背景
現状 apps/mobile 以外([対象パッケージ])にはテストがありません。まずは [対象ファイル/機能] を対象に追加します。

## 対象
[ファイルパスや関数名]

## 完了条件
- 既存のテスト(apps/mobile/test/ 配下)のスタイル・命名規約に倣う
- 正常系だけでなく、境界値・異常系もカバーする
- 対象パッケージに `test` スクリプトがない場合は package.json に追加し、turbo.json の `test` タスクが拾えることを確認する
- `pnpm test` (または `pnpm test --filter=<package>`) を実行し、追加したテストが通ることを確認する
```

## 5. リファクタリング

```
milkbox リポジトリの [対象範囲] をリファクタリングしてください。

## 動機
[なぜやるのか。可読性/重複解消/型安全性向上など]

## 制約
- 外部から見た挙動は変えない(振る舞いの変更が必要な場合は先に相談する)
- 過度な抽象化・将来の拡張を見越した先回り設計は避ける
- 変更は対象範囲に閉じる。関係ない箇所への手出しはしない

## 完了条件
- `pnpm lint` / `pnpm check-types` / (該当すれば) `pnpm test` が通る
- 挙動が変わっていないことを確認できる根拠を示す(既存テストが通る、または手動確認の記録)
```

---

## 6. Android ビルド関連作業

```
milkbox の Android ビルド周りで [作業内容] をしてください。

## 前提
- 作業前に docs/build-android.md を読み、3つのビルドシナリオ(EAS Build+Expoデバッグ / EAS連携ローカルビルド / 完全ローカルビルド)のうちどれに該当するか確認する
- apps/mobile/android/ ・ apps/mobile/ios/ は絶対にコミットしない(.gitignore で除外済み、managed workflow)
- apps/mobile/eas.json のプロファイルを変更する場合、なぜ変更が必要かを明記する

## 作業内容
[具体的な依頼: 新しいビルドプロファイル追加、署名設定変更、CI連携など]

## 完了条件
- git status で apps/mobile/android・apps/mobile/ios 配下のファイルが追跡対象になっていないことを確認する
- 変更が docs/build-android.md の記載と矛盾しないか確認し、矛盾する場合はドキュメントも更新する
```

---

## 7. 依存関係の更新

```
milkbox リポジトリの [パッケージ名] を [バージョン/最新] に更新してください。

## 対象
[apps/mobile の Expo SDK など、影響範囲が広いものは特に慎重に]

## 完了条件
- 破壊的変更の有無を changelog/リリースノートで確認し、影響を受けるコードを洗い出す
- pnpm-lock.yaml を更新する
- `pnpm install` → `pnpm lint` / `pnpm check-types` / `pnpm test` が通ることを確認する
- apps/mobile の依存を更新した場合、`npx expo prebuild` で生成し直しても問題なくビルドできるか確認する(docs/build-android.md 参照)
```

---

## テンプレート共通の使い方メモ

- 大きすぎるタスクは分割してから渡す(1テンプレート=1PR相当を目安に)
- 「完了条件」は削らずに残す。エージェントが自己検証せずに完了報告するのを防ぐため
- モバイル/Web/Desktopで挙動確認が必要なUI変更は、型チェック・lintだけで完了と判断しないことを明示する
